# SPX Chat 后台管理系统

后台入口：`/spxchat-systemadmin/admin.php`；登录页：`/spxchat-systemadmin/login.php`；退出由后台按钮 POST 到 `/spxchat-systemadmin/logout.php`。页面通过项目的 `../db.php` 使用 PDO 直接读写 MySQL，不调用应用 API。

## 首次管理员

后台会自动创建管理员、登录限制和审计相关的数据表。数据库中还没有管理员时，首次打开登录页会自动创建默认管理员 `ahtim`，密码按哈希形式存入数据库。登录页不会显示默认凭据；登录后请立即在“账号安全”修改密码。后台不提供公开注册入口。

同一来源 IP 和账号连续登录失败达到 5 次后冷却 10 分钟，达到 10 次后冷却 1 小时；成功登录会清除该组合的失败计数。

## 功能

- 总览、用户查询、充值记录和钱包流水查看
- 用户启用/停用，停用时撤销用户登录令牌；可重置用户密码
- 管理员可重置用户密码并撤销原登录令牌
- 钱包余额增加、扣减和设定目标余额；每次调整同时生成钱包流水与审计记录
- 提现通过/拒绝；拒绝时在事务中退回余额
- 充值、钱包流水、兑换、质押、推荐奖励查询
- 商品新增、编辑、上下架，订单完成或取消退款
- 客服工单、用户问题、反馈、FAQ、群组管理
- 管理员账号、角色权限、操作审计、CSV 导出和财务报表
- BSC USDT 收款地址设置与验证器最近心跳状态
- 系统设置中发布原生 Android APK、更新说明、SHA-256 与每版本下载统计

运营账号使用流程和权限说明见：[运营账号使用说明.md](运营账号使用说明.md)。

充值验真记录只读，钱包流水不允许手工改写；余额管理通过新增流水调整。链上到账仍由 `recharge_verifier.py` 验证和处理。

角色分为超级管理员、财务、客服和运营；敏感写操作会记录管理员、来源 IP、变更前后数据与操作原因。余额操作使用数据库事务、流水审计和请求去重，不直接覆盖而不留流水。取消待处理商城订单会同时退款和恢复库存；提现拒绝会同时退款。

## 管理后台代码结构

- `admin.php`：登录校验、写操作事务和页面入口。
- `admin_export.php`：CSV 导出处理，统一校验导出权限。
- `admin_queries.php`：钱包流水筛选和分页查询。
- `admin_wallet_labels.php`：钱包流水类型中文映射。
- `admin_navigation.php`：后台导航分组和模块名称。
- `admin_layout.php`：导航渲染，按当前管理员权限过滤模块。
- `admin.css` / `admin.js`：固定导航布局、流水表格样式和复制交互。

后台桌面端使用固定侧栏和独立内容区滚动；移动端自动切换为顶部横向导航。钱包流水支持用户、ID、交易哈希、类型、状态和日期筛选，地址与交易哈希默认截断并可复制完整值。

## Android 热更新

在后台“系统设置”上传 APK，填写 Android `versionName`、`versionCode` 和更新说明。版本代码必须大于当前发布值；App 按已安装包的 `versionCode` 判断是否提示更新。APK 必须保持 `applicationId` 为 `com.spx.chat`，并使用与用户已安装 App 完全相同的签名证书，否则 Android 系统会拒绝覆盖安装。每次正式构建都应递增 `android-native/app/build.gradle` 的 `versionCode`。

APK 存放在 `uploads/app-releases`，后台 PHP 上传上限为 500 MB；服务器需将 `upload_max_filesize` 和 `post_max_size` 配置为高于实际 APK 大小（`post_max_size` 还需略大于 APK）。App 下载时由 API 累加对应版本的下载次数，并在安装前校验 SHA-256。Android 8.0 及以上首次安装更新时，用户需在系统设置允许 SPX IM 安装未知应用，之后由 Android 系统安装器完成覆盖安装。

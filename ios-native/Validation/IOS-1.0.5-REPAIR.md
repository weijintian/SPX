## A 呼叫离线 B，B 上线即中断

明确根因：spxchat/auth.php 的 issueToken 在 B 登录时，将与 B 有关的所有 ringing / connected 通话标记 failed，包括 B 尚未收到且 callee_device 为空的新来电。

现在只保留“接收方登录 + ringing + 未绑定接收设备”的邀请。旧设备已认领的邀请、已接通通话、发起方换设备仍按原单设备登录规则结束；取消、拒绝和超时的通话不会复活。通话原有服务端超时规则继续有效。

iOS 补充：SDK 登录前注册来电观察者，收到早到邀请时先等待 SDK 就绪；离线等待期间短暂网络错误不直接终止邀请；独立的约一分钟等待超时负责收尾；取消及退出会取消旧拨号任务；SDK 接通回调取消响铃超时，避免打开麦克风时误超时。

## 2026-10-24 再次复查并修复

- 对照 Android ChatCall.java 与锁定 SDK 的 TUICallEngine.h，发现 iOS 使用 calls(userIdList:...)，Android 使用一对一 call。现统一使用头文件中确实存在的 call(userId:callMediaType:params:succ:fail:)；这是兼容 Android 的现有一对一调用方式，仍须用实际 Tencent 项目验证套餐、信令和音视频。
- iOS 原来把 SDK OFFLINE 回调直接当失败结束。现与 Android 一样保留业务邀请，在原始等待期限内间隔 8 秒重试并检查对方是否就绪；每次使用新房间号，记录已退役 SDK ID，忽略旧尝试的晚到回调。已拒绝、已取消、忙线和已超时不会触发该重试。
- SDK 确认接通即取消响铃超时并报告后端 connected，不再等麦克风打开才报告，减少临近超时接听被后端清理的窗口。
- 连点接听不会重复 accept；已经接通或已结束后的旧接听动作只取消该动作。增加“正在接通”状态，避免重复操作导致正常通话被结束。
- 拨号准备状态按业务通话 ID 归属，结束时释放；旧拨号任务完成或失败不再清除新呼叫的准备状态，也不弹旧错误。视频结束时显式停止远端订阅；旧通话摄像头错误不会污染新通话。
- 通话开始时取消正在进行的语音消息录制，减少录音、铃声和 RTC 争用音频会话。
- 群历史上下文补传 isGroup，显示成员名称；图片气泡按 Android 加载后的实际比例布局；文件和拍摄附件复制、相机照片编码移出主线程。
- 新增 CallFlowRegressionTests.swift 的 7 个 XCTest，覆盖音视频房间关联、退役回调、绑定 SDK ID、旧会话、原始离线期限和终态不重拨；增加图片横竖比例及窄屏布局断言。这些 XCTest 已写入但当前未执行。
- 再次执行源码结构扫描：62 个 Swift 文件、99 个字面量 API action 均可在本地后端找到；无扫描错误。服务端三个原文件和三个部署副本 PHP 语法均通过，副本字节一致。

以上验证未连接生产账号或发起真实通话；M4A / MP4 是容器及传输夹具，不代表设备录制、播放或摄像头已经验收。

## 通知实现

- 两端在线新消息系统通知、桌面角标代码、已读清理、点击通知跳转与账号校验。
- iOS 基于 REST 快照与去重 ledger 统计未读，包含请求代次/登录会话隔离；读取后清理本地和 APNs 已送达通知。
- Android 移除实时未读重复累加，重复事件不重复弹通知；按会话取消通知，静默汇总显示未读总数，支持权限恢复和设置开关。
- APNs 设备注册、单设备登录会话绑定、消息队列、可配置 worker 和签名 entitlement 检查已写入。服务端迁移、实际投递尚未联调。
- 用户没有 APNs 密钥和 Android 推送服务配置，因此退出 App 后的远程提醒尚未启用。普通消息通知不等于后台/锁屏 VoIP 来电。

## 验证边界

本地可执行检查的最终结果见 `ui-notifications-verification.json`。

- Swift 源码解析、局部结构/引用校验和 97 个字面量 API action 对照；这不是 Xcode 类型检查。
- 18 项隔离媒体上传检查、33 项推送参数/路由/禁用策略检查、9 项来电登录策略回归和 9 项签名配置测试。
- Android 改动的 Java 文件可以针对现有编译产物与缓存库定向编译；完整 Gradle 离线构建缺少三个腾讯依赖，尚未成功。
- 新增通知 ledger/route 的 XCTest 用例，当前 Windows 环境不能运行 Xcode/XCTest。
- 没有使用真实账号发消息、音视频通话、支付、领取红包、发布商品或修改公开 APK 发布记录。

需要先完成 Mac 构建、逐页设备对照及上述真实业务验收，才能判断整个 iOS 是否达到“全部与安卓一致且可用”。
